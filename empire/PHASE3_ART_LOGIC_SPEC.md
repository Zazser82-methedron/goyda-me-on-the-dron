## 1. Стиль 3D-моделей

Факт: все 38 GLB — честный low-poly без текстур (0 images у каждой), прямые PBR-цвета,
74–548 треугольников на постройку. Палитра уже единая (тёмное дерево `#1a0b02`, серо-коричневый
камень, красно-бордовые полотнища, золото/циан emissive). Проблема НЕ в качестве, а в повторном
использовании силуэта — 6 явных визуальных дублей (см. §4).

ТЗ для Blender-пайплайна (`tools/blender/`):

| Параметр | Стандарт |
|---|---|
| Геометрия | Flat shading, без normal-map |
| Треугольники | 1×1: 120–280 · 2×2: 250–650 · 3×3/чудо: 600–1400 · юнит: 180–450 |
| Материалы | 3–6 на постройку, максимум 8 на чудо, общая библиотека материалов |
| Текстуры | Не добавлять; если понадобятся — один atlas 512² на класс ассетов |
| Палитра | 70% земляное · 20% фракционный акцент (киноварь/охра) · 10% emissive-сигнал |
| Emissive | Только функциональный сигнал (горн/окно/кристалл/жаровня), 1-2 акцента максимум |
| Силуэт | Один читаемый признак на тип (колесо=ферма, труба=кузница, купол=обсерватория) |
| Посадка | Origin в центре footprint по XZ, ноль по нижней точке, фасад в локальный `+Z` |
| Вход | Обязателен `entry`-маркер на фасаде — для дороги/рабочих/транспорта (см. §2) |
| Вариативность | 2-3 варианта крыши/забора/навеса для повторяемых зданий |

**Приоритет: сначала 6 визуальных дублей, потом дороги/мосты/рельсы — не все 38 моделей разом.**

## 2. Связь построек, дороги/рельсы/мосты

### Как устроено сейчас (реально в коде)
`Tiling.js:12` — дорога/рельсы получают только 4-битную маску соседей N/E/S/W, пересобираются в
прямая/угол/T/перекрёсток. Мост — 1×1 тайл, просто поворачивается по маске.

Транспорт ищет BFS по тайлам `t.road`/`t.rail`, путь начинается у внешней клетки footprint —
**не у входа здания**. Отсюда:
1. Дорога не подключается к фасаду — только дорога к дороге.
2. Мост не различает вход/выход/пролёт/устой.
3. Рельеф учитывается только высотой центра — нет проверки уклона/опор.
4. Награда растёт с длиной пути (телега `6+0.4×длина`, поезд `10+0.5×длина`) — **игроку
   математически выгодно строить уродливые петли**. Это и есть системная причина «криво выглядит».

### План исправления
1. У каждого здания — `roadPort`/`railPort`/`servicePort` (клетка+направление на фасаде).
2. Дорожные модули: прямая, угол, T/перекрёсток-площадь, тупик-разворот, подъезд-к-зданию
   (утоптанная земля → доски/камень → крыльцо).
3. `roadSurface` по типу (тропа/грунтовка/мощение/мост) — задел на визуальный рост по эпохам.
4. Мост цепочкой: устой → пролёт(ы) → устой, ориентация фиксируется на первом тайле.
5. Рельсы: прямая, плавный поворот, стрелка, тупик, платформа станции, рампа пакгауза.
6. Путь транспорта — от порта к порту, не до края footprint.
7. **Убрать награду за длину маршрута** — заменить на факт доставленного груза (см. §7).

## 3. Ауры — Tropico-style (✅ P0-часть уже исправлена в этой сессии)

Подтверждённый баг: `GameState.js:241` создаёт `RingGeometry` под ауру **один раз при постройке
и добавляет в сцену навсегда** — видимость никогда не переключается. Отсюда «много радиусов
загромождают экран» — они физически всегда на сцене.

Нужный UX: радиус виден только когда здание выбрано (тусклый предпросмотр — при наведении/стройке),
скрывается при снятии выбора. Реализация — один переиспользуемый `Mesh` с масштабированием под
радиус конкретного здания вместо create/destroy каждый раз (см. код в отчёте Codex, применено).

## 5. Где нужны рабочие холопы

**Требуют:** ферма, рудник, жила (масштабируют выход 1-3 рабочими), кузница (включает
производство, не блокирует существование), рынок/приказ (запускает караван/сбор), плотник/
ремонтный двор (уже в Phase 2), станция/пакгауз (диспетчер для работы линии).

**Остаются пассивными:** палаты, избы, амбар, роща, стены, ворота, башни, кумирня, вече,
обсерватория, идолы — иначе микроменеджмент задушит.

## 7. Транспорт — переосмысление (сейчас декоративный генератор золота)

Телеги/поезд сейчас просто тикают доход по таймеру, не переносят реальные ресурсы. Новый принцип:
**транспорт физически переносит товар между узлами**; без связанной сети здание работает медленнее
или копит товар локально. Доход = `доставленный груз × цена × спрос`, не длина маршрута.

Новые типы: крестьянская подвода (эпоха I, еда/дерево/камень), купеческий обоз (эпоха II, дорогой
товар к Торгу — приоритетная цель налёта), рельсовая дрезина ремонтников (эпоха III, чинит износ
рельсов/мостов/станций — даёт смысл Ремонтному двору), бронепоезд «Гойда» (поздняя ветка,
переброска дружины между станциями или краткий залп, не замена армии).
